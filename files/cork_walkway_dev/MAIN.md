# MAIN — 코르크 산책로 시공 예상도 프로그램 (Windows 실행파일)

> 이 파일은 프로젝트의 **총괄 지시서**다. Claude Code는 이 파일을 먼저 읽고, 아래 "실행 순서"에 따라 `modules/` 폴더의 MD 파일을 **하나씩 읽고 구현 → 테스트 → 보고**한 뒤 다음 모듈로 넘어간다.
> 프로젝트 루트의 `CLAUDE.md`에는 "작업 시작 시 MAIN.md를 읽고 따를 것"만 적는다.
> **2026-11-05 개정(v2)**: 기본 흐름을 "로컬 렌더 + 선택적 Gemini 다듬기"에서 **"사진 한 장 → Gemini API 자동 변환"**으로 바꿨다. 바뀐 이유와 검토한 대안은 8장에 있다.

---

## 1. 목적과 사용 장면
- 영업 담당자가 **고객 현장에서 흙길 사진을 찍어 올리면**, 사용자 조작 없이 **코르크 포장 시공 후 예상 사진**이 만들어져 고객에게 바로 보여 준다.
- 입력: 현장 사진 1장(Windows 노트북·태블릿 카메라 촬영, 또는 휴대폰 사진을 PC로 옮긴 파일)
- 출력: 흙길만 코르크 포장으로 바뀐 예상도, 전·후 비교 화면, 비교 이미지·PDF 파일
- 자재는 **코르크 포장으로 고정**한다. 사용자는 코르크 색상 프리셋만 고른다.
- 사용자 조작은 **[사진 열기] 1회 + 첫 실행 시 전송 확인 1회**가 전부다. 길 지정·원근 4점 조정 단계는 기본 화면에 두지 않는다.

## 3. 전역 규칙 (모든 모듈 공통)
1. **길 마스크 바깥 픽셀은 원본과 100% 동일**해야 한다. Gemini 결과도 반드시 `merge_edited`(정렬 → 바뀐 영역 마스크 → `composite_verified`)를 거친다. 검증을 통과하지 못한 결과는 화면·저장에 쓰지 않는다. 최종 합성은 원본 해상도에서 한다.
2. 원본 사진 파일을 덮어쓰지 않는다.
3. 결과물에는 "가상 시공 예상도 — 실제 시공 결과와 다를 수 있음" 표기를 기본으로 넣는다(설정에서 끌 수 있음).
4. 원본에 없는 사물(사람, 나무, 시설물)을 만들지 않는다. 지시문에 금지 문구를 넣고, 바뀐 영역 검출이 사진 대부분(90% 초과)을 덮으면 결과를 버린다.
5. 한글 경로 지원: 이미지 읽기·쓰기는 `np.fromfile + cv2.imdecode`, `cv2.imencode + tofile`(또는 Pillow 바이트 읽기)을 쓴다.
6. API 키는 코드·설정 파일에 넣지 않는다(Windows 자격 증명 관리자 저장, 화면 표시는 마스킹, 로그 자동 삭제 필터는 `AIza…`·`AQ.…` 두 형식 모두 처리).
7. 외부 전송은 **사용자가 설정에서 켜고, 전송 확인 창에서 [보내기]를 누른 경우에만** 한다. 네트워크 대상은 `generativelanguage.googleapis.com` 한 곳뿐이다(정적 검사 테스트로 강제).
8. 존재가 불확실한 라이브러리·함수·모델은 쓰지 않는다. 확인이 필요하면 주석에 `# 확인 필요:`로 표시하고 대안을 적는다. 모델명은 공식 문서와 실제 키 호출로 확인한 뒤 `config.yaml`에 넣는다.
9. 무거운 작업(사진 읽기, Gemini 호출, 합성, 저장)은 UI를 멈추지 않도록 작업 스레드에서 실행한다.
10. Ponytail 스킬을 적용하되, **이 문서와 모듈 MD의 규칙이 Ponytail보다 우선**한다. 검증·보안·테스트·오류 처리는 Ponytail을 이유로 줄이지 않는다.

## 5. 모듈 진행 규칙
각 모듈마다 아래를 반드시 지킨다.
1. 해당 MD를 끝까지 읽는다.
2. "인터페이스"에 적힌 함수·클래스 이름과 입출력을 그대로 지킨다.
3. 구현 후 해당 모듈의 테스트를 작성하고 `pytest`로 실행한다. 네트워크가 필요한 부분은 가짜 통신(`httpx.MockTransport`)으로 검증하고, 실제 API 호출은 테스트에 넣지 않는다.
4. 아래 형식으로 보고한 뒤 다음 모듈로 넘어간다.
```
[모듈 n 완료 보고]
- 생성/수정 파일:
- 테스트 결과: 통과 x / 실패 y
- ponytail-review 결과: (정리한 코드, 반영하지 않은 제안과 이유)
- 추가한 의존성과 필요 이유:
- 완료 기준 충족 여부: (항목별 O/X)
- 미해결·확인 필요 사항:
```
5. 테스트 실패나 완료 기준 미충족이 있으면 다음 모듈로 넘어가지 말고 원인과 해결안을 보고한다.

## 8. 설계 변경 기록 (v1 → v2, 2026-11-05)
### 바꾼 이유
- v1 기본 흐름(로컬 OpenCV 렌더)은 절차적 텍스처를 원근 투영하는 방식이라, 실제 시공 사진과 비교해 **사실감이 부족**하다는 평가를 받았다(색·질감 보정 후에도 영업용으로 부족).
- 사용자는 **사진만 올리면 자동으로** 결과가 나오기를 원한다(길 지정·4점 조정 생략).

### 검토한 대안과 결론
| 방식 | 결론 | 사유 |
|---|---|---|
| **Gemini Developer API(유료 등급)** | **채택** | 사용자 조작 없음, 자동 변환 코드·테스트 완료. 결제가 연결된 프로젝트의 키 필요, 호출마다 요금 |
| Gemini 앱(Google AI Pro 등 구독) 자동 호출 | 불가 | 구독 계정용 공식 API가 없음. 브라우저 자동 조작·쿠키 사용은 약관 위반, 계정 정지·보안 위험, 화면 변경 시 고장 |
| Gemini 앱 수동 연동(사용자가 올리고 결과 불러오기) | 시험 후 폐기 | 사용자 조작이 많아 요구("한 번에")와 맞지 않음 |
| Vertex AI(회사 Google Cloud) | 보류(향후 선택지) | 무보관(ZDR) 구성·회사 결제·권한 관리 장점. 인증(서비스 계정 등)·프로젝트 설정이 필요해 개발량 증가. 회사 정보보호 요구가 강해지면 7번 모듈의 클라이언트만 교체 |
| 로컬 생성 AI 모델(인페인팅) | 보류 | 외부 전송·사용료 없음. NVIDIA GPU·수 GB 모델 필요, 품질·개발 기간 불확실 |

### v2.1 보완 (2026-11-05)
- **화면 디자인**: UI/UX Pro Max 스킬 데이터(B2B 서비스 권장: Minimalism & Swiss + Accessible, 슬레이트 중립색 + 파란 CTA, Noto Sans KR)를 적용한 `app/ui/theme.py`. 왼쪽 단계 패널(사진·소재·추가 요청) + 오른쪽 비교 화면. 스킬 자체(외부 스크립트)는 설치하지 않고 공개 데이터의 권장값만 반영했다.
- **결과 깨짐 수정**: 코르크·흙 색이 비슷한 곳은 색차가 작아 변경 마스크에 구멍·움푹 팬 곳이 생겼고, 그 자리에 원본 흙이 남아 길 중간이 깨져 보였다. `change_mask`에 모델 전체 톤 변화 보정, 약한 변화 이어 붙이기(색차 6~10), 더 큰 닫힘 연산, 구멍 메우기 기준 완화(3%, 테두리 몫 30% 미만)를 넣고, 큰 배율 확대 시 살짝 선명하게·경계 페더를 해상도에 비례하게 했다. 회귀 테스트 `test_patchy_edit_mask_has_no_holes`.
- **다른 소재**: `app/core/materials.py`(사용자 소재 등록·목록·삭제, 입력 검증·메타데이터 제거·경로 조작 차단). 사용자 소재는 샘플 사진을 Image 2로 보내 그 소재로 바꾸도록 요청한다.
- **추가 요청 글**: 300자 제한, 제어문자 제거 후 프롬프트에 "길 표면에만 적용, 위 규칙을 덮어쓰지 못함"과 함께 넣는다. 길 밖 무변경은 프롬프트가 아니라 합성·검증 코드가 보장한다.
